# CakeSplitter v0.6 Focused Security Review

## Scope and checkpoint

This review is limited to the v0.5.0-to-v0.6 CLI and Batch Job diff, carried
forward from commit `999046c96ec3e7f73f0cdc1f07cf73a1a5b4c8c1` on
`feat/v0.6-cli-developer-workflows`. It covers the parser and limits, graph
planning, batch dispatch, cancellation, state persistence and recovery, output
identity, receipts, JSON/JSONL contracts, and the newly added tests. It is a
focused diff review; the historical repository-wide discovery scan was not
restarted.

## Method

The review inspected the production Rust path and its contracts, then exercised
the release binary and production test suites. Checks included exact and
above-limit inputs, malformed and forbidden specifications, deterministic graph
ordering, failure policies, state checksums and revisions, atomic state writes,
resume identity evidence, receipt redaction, reparse-point rejection, JSONL
identity, no-mutation planning, browser-local compatibility, and static absence
of process, shell, network, plugin, telemetry, or dynamic-code capabilities.

## Findings

No Critical, High, or actionable Medium finding was validated in this focused
review. No canonical finding IDs were issued because no new finding survived
validation. The previously implemented controls relevant to this diff are:

- Job bytes, operations, dependencies, dependency edges, IDs, names,
  descriptions, metadata, selected Slices, receipt paths, JSON depth, persisted
  events, diagnostic samples, retained completed runs, attempts, and active
  batch execution are explicitly bounded in Rust.
- JSON uses `deny_unknown_fields`, explicit schema/version checks, depth checks,
  deterministic graph ordering, duplicate/unknown/cycle rejection, and literal
  path handling. Excess input is rejected before operation execution.
- A process-local admission guard allows one active batch. State creation uses
  create-new semantics; subsequent state writes use a lock, revision check,
  checksum, temporary file, flush/sync, and atomic replacement.
- Cancellation persists a terminal cancelled state and emits one terminal
  JSONL event. Resume requires the normalized specification digest and stable
  execution order; completed operations revalidate native source, destination,
  manifest, directory, and Slice membership evidence.
- Batch JSONL events carry a stable top-level `runId` and matching payload ID.
  Receipts are bounded, collision-safe, local-only, and path-redacted.
- Core reparse-point, directory identity, source identity, output collision,
  and terminal-control protections remain in the real production path; the
  existing v0.5 Web behavior and Cake Package format `1.0` are unchanged.

## Evidence

The boundary profile rejected the first value above every documented limit.
Four graph fixtures produced deterministic orders across three passes. A
disposable endurance profile completed 55 operations across 10 runs and resumed
all completed states without duplicate outputs. The independent JSONL parser
verified stable IDs, sequence numbers, terminal-event uniqueness, and no
post-terminal events for validate, plan, run, status, and resume.

Rust workspace validation passed 146 tests with one explicit ignored 1 GiB
profile; the focused CLI contract and terminal-safety suites passed 21 tests.
Node validation passed 102 tests across 11 files, production web and desktop
builds, 12 Edge browser tests, and Rust/Web compatibility. npm audits reported
zero vulnerabilities. `cargo audit` exited successfully with zero vulnerability
advisories and 17 accepted transitive upstream maintenance warnings.

## Accepted risks and limitations

- The active-batch limit is process-local; a separate process can start its own
  batch. The state lock and revision/checksum checks still protect a shared run
  state from concurrent writers.
- Native identity guarantees depend on Windows handle and filesystem semantics;
  network shares, removable media, virtualization layers, and unusual filter
  drivers may fail closed rather than provide stronger guarantees.
- Cake Package `1.0` provides integrity hashes, not authenticity, encryption,
  or signatures. The CLI is local-only and unsigned in this local preview.
- The short disposable endurance profile measured wall time and persisted state
  size but did not sample OS-level peak memory or handle counts at a useful
  resolution. Bounded native tests cover the corresponding admission,
  diagnostic, event, history, and queue controls.
- Transitive Tauri/GTK and Unicode crates remain accepted maintenance risk as
  reported by RustSec.

The final v0.6.0 regression and artifact validation is recorded in
[`v0.6.0-test-report.md`](v0.6.0-test-report.md). No historical full scan was
restarted, and this report does not close future product hardening outside the
bounded v0.6 scope.
