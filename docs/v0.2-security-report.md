## False positives

None of the 12 final findings is classified as a false positive. Discovery
candidates that lacked a reachable trust-boundary crossing or retained adequate
counter-controls were closed before reporting. In particular, the review found
no network egress/SSRF issue, no path-traversal escape in accepted manifests, and
no authentication issue because the project has no account or remote service
surface.

## Additional hardening

- Manifest input is limited to 16 MiB before JSON decoding.
- JSON nesting is limited to 16 before decoding.
- Manifest Slice count/table is limited to 50,000.
- Portable names are limited to 200 UTF-8 bytes and reject Windows reserved
  names, separators, control characters, and non-portable edge whitespace.
- Browser selections are limited to 10,000 Files.
- Browser compatibility Split/Merge is limited to 256 MiB; Split is limited to
  1,000 downloads.
- Worker commands, Files, directory handles, arrays, manifest text, numbers,
  Blobs, progress, inspection evidence, and result shapes are validated at
  runtime on both sides of the Worker boundary.
- Native unsupported no-replace platforms fail closed.

## Atomic finalization contract

The native core uses `renameat2(RENAME_NOREPLACE)` on Linux/Android,
`renamex_np(RENAME_EXCL)` on Apple platforms, and `MoveFileExW` without
`MOVEFILE_REPLACE_EXISTING` on Windows. It checks the staged file's stable
filesystem identity, size, and SHA-256 immediately before publication and opens
the final name to verify the same facts afterward. Collision errors preserve the
raced-in destination. Ambiguous path names are not automatically deleted.

## Remaining accepted risks

- SHA-256 provides integrity, not publisher authenticity or a signature.
- Browser Merge buffers the complete rebuilt Cake, and browser Split buffers one
  completed Slice. The 256 MiB limit bounds but does not eliminate memory
  pressure on constrained devices.
- Browsers may throttle multiple downloads or choose collision-renamed download
  filenames. CakeSplitter does not control browser download history or the final
  download destination.
- Browser v0.2.1 cannot operate on packages requiring more than 10,000 selected
  files and cannot Split into more than 1,000 downloads, although Manifest 1.0
  supports 50,000 Slices.
- A native Split interrupted by a late collision can leave already-published,
  verified Slices without a final manifest. They are incomplete, not reported
  complete, and left for explicit operator cleanup.
- A concurrent writer that retains control of the output directory can replace
  a staging or final name after a check. CakeSplitter detects an identity or
  digest mismatch and does not return verified success, but it deliberately
  does not delete the ambiguous replacement path.
- Atomic rename semantics on unusual or remote filesystems ultimately depend on
  the operating system/filesystem provider. Unsupported platforms fail closed;
  not every network filesystem was exercised.
- A package can be malicious while remaining internally hash-consistent. Do not
  treat successful verification as proof that its contents are safe to execute.

These risks are documented, bounded where possible, and do not leave an
unresolved Critical or High issue.
