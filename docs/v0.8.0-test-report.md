# CakeSplitter v0.8.0 Test Report

## Result

**PASS** for the v0.8.0 public pre-release candidate.

The final source candidate was validated from a clean isolated copy that did
not reuse the repository's Rust target directory, frontend build output, or
test reports. Cake Package format 1.0, CLI schema 1, and Batch Job schema 1
remain unchanged.

The RustSec run reported 17 accepted transitive maintenance or unsoundness
warnings. None was a vulnerability advisory, and no direct practical exploit
path was identified for the supported CakeSplitter workflows. These remain
dependency-maintenance inputs rather than hidden passing results.

## Compatibility and privacy evidence

- Rust-generated Packages rebuilt in Web with identical bytes and SHA-256.
- Web-generated Packages rebuilt in Rust with identical bytes and SHA-256.
- Manifest, Slice membership, portable filename, numeric, and resource-limit
  rejection remained aligned across runtimes.
- Production browser tests observed no selected-content transmission.
- PWA tests preserved same-origin canonical shell caching, selected-data cache
  exclusion, offline startup, explicit waiting-worker activation, and active
  task fencing.
- Direct Folder Mode remained disabled and no browser filesystem output adapter
  was registered.

## Fresh-clone gate

The signed release commit and tag must pass a separate clean-clone build and
test gate before push, followed by public-clone and downloaded-asset
verification after publication. Those publication-state checks are recorded in
the final publication report rather than pre-claimed here.

## Conclusion

The source candidate passed the complete pre-publication matrix. No test failure
or compatibility drift blocks the v0.8.0 pre-release.
