## Validated findings and remediation

### `csf_f9beb2b9f7bec8cd8592d4dc` — Low

The privacy model grouped Desktop and Web under an unqualified "no automatic
update check" promise even though supporting browsers register the same-origin
service worker and may check or install the static PWA shell.

Remediation:

- public cross-runtime wording now distinguishes the absent Desktop updater and
  project-managed Web update endpoint from the browser-managed same-origin PWA
  lifecycle;
- documentation states that service-worker and static-shell requests never
  contain selected content or task metadata; and
- the existing same-origin, canonical-response, cache-allowlist, explicit
  activation, and active-task controls remain unchanged.

### `csf_f66fe420c0ddbb915a7501fd` — Low

The privacy model retained an unversioned private-preview acquisition and
checksum route beside the public v0.8.0 release route.

Remediation:

- the current guide names the authorized `Ianlovesneko/CakeSplitter` GitHub
  pre-release as the only v0.8.0 source;
- it requires both `SHA256SUMS.txt` and `artifact-manifest.json`; and
- it explicitly states that earlier private-preview artifacts are not the
  v0.8.0 public distribution source.

A stale architecture sentence saying no public download was available was also
corrected as publication QA. Attack-path analysis found no lower-privileged or
attacker-controlled path for that sentence, so it was not a security finding.

## Remediation verification

- the affected documentation no longer contains the ambiguous private-preview
  route or the stale no-public-download statement;
- public privacy wording consistently distinguishes Desktop updater behavior
  from browser-managed same-origin PWA checks;
- `npx.cmd vitest run apps/web/src/pwa.test.ts apps/web/src/service-worker.test.js`
  passed 9 focused tests; and
- the product runtime was not changed by these documentation fixes.

## Preserved controls

- strict Manifest, Slice, portable-filename, numeric, and resource-limit
  validation;
- Windows filesystem identity binding and reparse-point rejection;
- atomic no-replace publication and final identity/content verification;
- bounded native admission, persistence, recovery, history, and diagnostics;
- runtime IPC and Worker message validation;
- disabled Web Direct Folder Mode;
- same-origin canonical PWA shell caching without selected data;
- terminal-control and bidirectional-control escaping; and
- no upload, telemetry, analytics, remote checksum, cloud fallback, shell,
  process, Tauri HTTP, arbitrary filesystem, or project-managed updater
  capability.

## Accepted risks

- Windows executables and the NSIS installer are unsigned and may trigger
  SmartScreen.
- The signed Git tag authenticates source, not the unsigned Windows binaries.
- SHA-256 provides integrity, not publisher authenticity.
- A supporting browser may contact the same origin for service-worker and
  static-shell lifecycle requests; selected content and task metadata are not
  included.
- Installer bytes may vary across Windows toolchain environments.
- Browser Compatibility Mode remains constrained by memory, download behavior,
  and platform limits.
- Cake Package 1.0 is not encrypted, compressed, signed, or an authenticated
  archival format.

## Final recommendation

No unresolved Critical, High, Medium, or Low security finding remains in the
v0.8.0 publication candidate. Proceed to signed-tag, artifact, fresh-clone, and
GitHub publication gates.
