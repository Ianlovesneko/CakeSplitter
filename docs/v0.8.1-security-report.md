# CakeSplitter v0.8.1 Security Report

## Result

**PASS** for the scoped development-toolchain remediation. Publication remains
gated on the complete release-validation, signed-tag, artifact, and public
fresh-clone checks.

- Critical: 0
- High after remediation: 0
- Moderate: 0
- Low: 0

## Advisory scope

The maintenance release addresses
[`GHSA-mh99-v99m-4gvg`](https://github.com/advisories/GHSA-mh99-v99m-4gvg),
also identified as CVE-2026-14257. The advisory affects `brace-expansion`
versions through 5.0.7 and describes unbounded expansion length causing an
out-of-memory denial of service.

The v0.8.0 lockfile resolved two affected development-only copies:

| Root | Dependency path | Affected version |
|---|---|---|
| ESLint | `eslint@9.39.5` → `minimatch@3.1.5` → `brace-expansion` | 1.1.16 |
| TypeScript ESLint | `typescript-eslint@8.64.0` → `@typescript-eslint/typescript-estree@8.64.0` → `minimatch@10.2.5` → `brace-expansion` | 5.0.7 |

The five High objects reported by npm were the root package, the
`minimatch` propagation, two ESLint configuration packages, and ESLint itself.
They all traced to the same advisory source.

## Runtime reachability

Before remediation:

- `npm audit --omit=dev --json` returned exit 0 with zero findings;
- `npm ls --omit=dev brace-expansion --all` returned an empty tree;
- no CakeSplitter product source imported `brace-expansion` or `minimatch`; and
- existing Web and Desktop production output contained no matching package or
  advisory string.

No evidence indicated that the vulnerable path was included in shipped Web,
Desktop, CLI, or Batch runtime dependencies. The realistic exposure was
development/CI availability if untrusted tooling input reached the expansion
path.

## Remediation design

No patched 1.x `brace-expansion` release exists, while ESLint 9.39.5 requires
`minimatch` 3.x and its 1.x `brace-expansion` range. The supported minimum
remediation is therefore:

- update the direct ESLint requirement to `^10.8.0`;
- directly declare `@eslint/js@^10.0.1`, which the repository imports;
- let npm regenerate the lockfile normally;
- retain TypeScript ESLint 8.64.0 because its peer range explicitly supports
  ESLint 10 and its `minimatch` range accepts the patched dependency; and
- resolve all remaining paths to `brace-expansion@5.0.8`.

No override, manual lockfile integrity edit, or `npm audit fix --force` was
used. Product code and security controls were not changed by the dependency
remediation.

## Lifecycle and supply-chain review

The repository defines no install lifecycle script. The lockfile marks:

- `esbuild@0.28.1` with its expected `node install.js` platform-binary
  postinstall; and
- optional `fsevents` packages with their macOS `node-gyp rebuild` install
  script, which is not installed or executed on Windows.

The responsible direct packages are established ESLint project packages. The
update introduced no similarly named replacement, alternate registry,
dependency alias, Git URL, arbitrary download script, or new product runtime
dependency. License and NOTICE changes are reviewed against the regenerated
machine-readable inventory before publication.

## Preserved security and privacy controls

- strict Manifest, Slice, portable-filename, numeric, and resource-limit
  validation;
- Windows filesystem identity binding and reparse-point rejection;
- atomic no-replace publication;
- bounded native task admission, persistence, recovery, history, and
  diagnostics;
- runtime IPC and Worker message validation;
- disabled Web Direct Folder Mode;
- selected-data exclusion from the PWA cache;
- terminal-control and bidirectional-control escaping; and
- no upload, telemetry, analytics, remote checksum, cloud fallback, shell,
  arbitrary-process, updater, or unrestricted filesystem capability.

## Accepted limitations

- Windows binaries remain unsigned and may trigger SmartScreen.
- The signed Git tag authenticates source, not Windows executables.
- Cake Package 1.0 provides SHA-256 integrity, not publisher authenticity.
- Browser Compatibility Mode remains subject to memory, download, and platform
  limits.
- RustSec transitive maintenance or unsoundness warnings remain separately
  reviewed; a warning is not reported as a vulnerability without a validated
  CakeSplitter attack path.

## Preservation

Release are not modified. `pre-v0.8-remote-backup` remains fixed at
`6453eaee6f6b86a71b79e26dc535f2166171f781`. No v0.9 functionality is part of
