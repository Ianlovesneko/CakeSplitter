# CakeSplitter v0.4.0 Release Notes

CakeSplitter v0.4.0 is an early preview that adds a native Windows desktop
runtime for resumable large-file workflows while preserving the local-only Web
app, Rust CLI, and Cake Package format 1.0 interoperability.

## What it does

- splits a local file into numbered, SHA-256-verified `.slice` files and a
  `.cake.json` manifest;
- inspects and verifies package completeness, membership, and Slice hashes;
- rebuilds the original file only after exact verification;
- interoperates between Rust, CakeSplitter Desktop, and SplitTheCake Web using
  Cake Package format 1.0; and
- performs all file processing locally, without upload, accounts, analytics,
  telemetry, remote checksums, or cloud fallback.

## Native desktop preview

CakeSplitter Desktop is available as an unsigned Windows 10/11 x64 NSIS
preview. It provides native file and folder selection, one active streaming
worker, a bounded persistent task queue and history, pause at verified Slice
boundaries, checkpoint restart recovery, structured task diagnostics, and
explicit Clear All controls.

The native runtime uses Windows volume/file identity, retained directory
authority, reparse-point rejection, content binding, and atomic no-replace
publication. It fails closed if a selected source, package, Slice, output
directory, or parent directory cannot be proven to be the object the user
authorized.

## Security hardening

The sealed v0.4 security review validated three Medium and four Low findings.
All seven are remediated:

- output-directory rebinding is blocked across Slice and final-manifest
  publication;
- task admission, recovery, history, metadata, plans, and enumeration are
  explicitly bounded in Rust;
- same-path and same-size source/package/selection replacement is rejected
  across execution and restart;
- streaming Split integrity and durable Merge package binding are revalidated;
- package enumeration and bootstrap recovery are bounded and fail closed; and
- Clear All transactionally removes task, history, and quarantine metadata and
  fences stale writers.

No unresolved Critical, High, or actionable Medium issue remains. The final
bounded release diff produced no new plausible security candidate.

## Install and run

For the native preview, obtain the installer and `SHA256SUMS.txt`, verify the
installer hash, then follow
[`desktop-installation.md`](desktop-installation.md). The installer is unsigned,
so Windows SmartScreen may show an unknown-publisher warning.

To run the Web app or CLI from source:

```powershell
npm ci
npm run dev
cargo run --locked -p cakesplitter-cli -- --help
```

To build the native installer from source:

```powershell
npm ci
npm --workspace @cakesplitter/desktop run tauri:build -- --bundles nsis
```

## Compatibility and limits

Application version `0.4.0` still reads and writes Cake Package format `1.0`.
The portable format version was not changed.

Desktop support is Windows x64 on local filesystems with stable native
identity. Network shares, removable media, cloud-synchronized folders,
virtualized paths, and unusual filter drivers may fail closed. Restart recovery
continues at committed Slice boundaries; it is not arbitrary-byte resume.

Browser Direct Folder Mode remains disabled. Compatibility Mode limits Split
and Merge to 256 MiB per operation, Split to 1,000 downloads, and package
selection to 10,000 files. Browser memory, Blob, quota, download, and platform
limits may be lower.

Cake Package 1.0 provides SHA-256 integrity, not package authorship,
encryption, signatures, or backup redundancy.

## Not included

This release does not include macOS, Linux, ARM64, code signing, automatic
updates, background services, plugins, a marketplace, compression, encryption,
PAR2, cloud integration, accounts, or AI features. Cake Package is a project
format, not an industry standard.
