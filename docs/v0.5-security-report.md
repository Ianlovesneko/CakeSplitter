# CakeSplitter v0.5.0 Security Report

## Scope and method

The focused security diff review compared the v0.5 implementation with the
immutable v0.4.0 local release baseline. The review covered queue admission,
scheduling, conflicts, preflight, retry/recovery, history, receipts,
diagnostics, redaction, storage cleanup, reveal, IPC, persistence, and task
state transitions. It used production-path Rust/desktop harnesses and the
repository threat model; no historical full-repository scan was restarted.

Ten candidates were validated: four Medium, five Low, and one suppressed
false positive. No Critical or High finding was identified.

## Medium findings remediated

### CS-V05-DESKTOP-EXPORT-RECEIPT-DIRECTORY-RACE

Before the fix, replacing the selected output directory after selection caused
the receipt helper to create the file in the replacement directory. The fix
retains native directory and ancestor handles, compares the selected
fingerprint, revalidates immediately before publication, and returns
`destination_identity_changed` on instability. The unchanged-equivalent race
harness now fails closed with no receipt in the replacement directory.

### CS-V05-DESKTOP-DIAGNOSTIC-DIRECTORY-RACE

Before the fix, a replacement parent received a generated diagnostic bundle.
Diagnostic export now holds the same native directory authority and revalidates
before creation and before every bounded file write. The post-fix harness
returns an identity error and publishes no bundle to the replacement.

### CS-V05-DESKTOP-DIAGNOSTIC-PATH-REDACTION-GAP

Before the fix, non-profile drive and UNC paths could appear in technical
diagnostics. The shared redactor now masks drive-root and UNC path spans while
protecting ordinary URLs, and keeps only a safe leaf when detail is explicitly
requested. The production redaction tests and independent harness confirm D:
and UNC paths are masked.

### CS-V05-CORE-HISTORY-ORPHANED-PARTIALS

Before the fix, bulk failed-history deletion removed a row while leaving its
identity-owned `.partial` file. Failed-history cleanup now enumerates valid
failed records, removes only the checkpoint-owned partial, and deletes the row
after cleanup. Checkpoint-bearing terminal history is excluded from blind
retention pruning and bounded separately. The production-path orphan harness
now confirms the row and owned partial are both removed.

## Accepted Low risks

- `CS-V05-DESKTOP-IPC-EXPORT-PATH-DISCLOSURE` is closed by the focused v0.5
  fix: the absolute export path is native-only; the renderer receives a
  display name and reveal token.
- `CS-V05-DESKTOP-REVEAL-SPAWN-FLOOD`: a valid reveal token remains reusable for
  its 30-minute local lifetime; the registry is capped at 20 entries. The
  action is explicit and local. One-shot/rate-limited reveal remains a future
  hardening item.
- `CS-V05-DESKTOP-CLEAR-COMPLETED-CONFIRMATION-BYPASS`,
  `CS-V05-DESKTOP-CLEAR-FAILED-CONFIRMATION-BYPASS`, and
  `CS-V05-DESKTOP-CLEAR-QUARANTINE-CONFIRMATION-BYPASS`: native IPC commands
  remain callable without the renderer's optional confirmation prompt. The
  operations are local, bounded, terminal-only, and have no remote impact;
  native confirmation authority is deferred.

`CS-V05-CORE-NATIVE-ALIAS-CONFLICT-BYPASS` was suppressed: the production
Windows reparse-point preflight returned `unsafe_filesystem_path` before
admission and no sink was reached.

## Validation evidence

The focused runtime suite, desktop type-check, receipt/diagnostic race
harnesses, redaction harness, and orphan cleanup harness passed after the
fixes. Full v0.5 validation results are recorded in
[`v0.5-test-report.md`](v0.5-test-report.md).

`npm audit` and `npm audit --omit=dev` report zero vulnerabilities. `cargo
audit` exits successfully with zero vulnerability advisories, while reporting
17 unmaintained/unsound upstream warnings in the Tauri/GTK and Unicode
transitive graph. They are outside the validated Windows application paths and
remain accepted dependency-maintenance risk for this unsigned local preview.

## Remaining limitations and accepted risks

Native filesystem guarantees depend on Windows identity and handle semantics;
network shares, virtualized folders, removable media, and unusual filter
drivers may fail closed. Cake Package 1.0 has integrity hashes but no
authenticity, encryption, or signature. The unsigned installer is a private
preview. Public GitHub publication is deferred until v0.8.0.
