## Packaged desktop runtime

The Windows x64 NSIS installer was built, installed for the current user,
reinstalled over preserved compatible state, and uninstalled. Installation did
not request elevation. The installed executable reported file and product
version 0.4.0, the UI displayed application version 0.4.0 separately from Cake
Package format 1.0, and the runtime opened no TCP connection during the test.

Installed-app workflows passed:

- a real 64 MiB source in paths containing spaces and non-ASCII characters was
  split, inspected, verified, and rebuilt byte-for-byte with SHA-256
  `dfc51ae1eca42d151aa28c7dff28b433402001d657891da7b026d76d22c09234`;
- replacing the selected output parent before execution produced a structured
  identity error, created no task, and published no file or manifest;
- selecting 65,537 package entries exceeded the 65,536 native enumeration
  bound before a task/result was created;
- 64 authentic interrupted tasks loaded, a further admission failed with
  `task queue is full` and left no record, and a 65th persisted recovery record
  was quarantined rather than resumed;
- after the focused finalization fix, production **Clear All** reduced both
  `tasks` and `quarantine` to zero while preserving SQLite integrity;
- close-during-work presented explicit keep-open, cancel, and checkpoint
  interrupt choices; and
- uninstall removed the program, shortcut, and registration while preserving
  documented local recovery data. Reinstall did not duplicate tasks.

The first final Tauri build encountered a stale absolute path inside an external
generated Cargo build cache after that validation directory had been renamed.
Only the generated external build cache was removed; the identical build then
passed. This was an environment/cache artifact, not a source failure.

## Security and compatibility

`npm audit` and `npm audit --omit=dev` reported zero vulnerabilities. `cargo
audit` scanned 463 locked crates, reported zero vulnerability advisories, and
reported 17 accepted informational warnings documented in the security report.

The compatibility matrix covered empty, one-byte, exact-boundary, final-short,
Unicode, and multi-extension packages in both runtime directions. Every
successful rebuild matched exact size, bytes, and SHA-256, and malicious
manifests were rejected. Application version 0.4.0 continues to read and write
Cake Package format version 1.0.

The complete source, browser, native-runtime, package, security, and large-file
