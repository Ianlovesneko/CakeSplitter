# CakeSplitter v0.6 Test Report

Application version: `0.6.0`
CLI schema: `1`
Batch Job schema: `1`
Cake Package format: `1.0`

This report records the final v0.6.0 local-release validation matrix. Public
GitHub publication remains intentionally deferred until v0.8.0; v0.7 work is
out of scope.

## Rust

All commands used the lockfile. Native Cargo build/test commands used a
dedicated external writable target directory after the repository target
directory reproduced a Windows build-script error (`The system cannot find the
file specified`).

| Command | Result |
| --- | --- |
| `cargo fmt --all -- --check` | PASS |
| `cargo clippy --locked --workspace --all-targets --all-features -- -D warnings` | PASS; zero warnings |
| `cargo test --locked --workspace` | PASS; 146 passed, 0 failed, 1 explicit 1 GiB profile ignored |
| `cargo build --locked --workspace --release` | PASS |

The focused CLI contract suite passed 16 tests and terminal-safety passed 5
tests with the external target directory. The production workspace suites also
covered cancellation, resume, output identity, package identity, queue
admission, state integrity, receipts, and bounded queue endurance.

## Environment and artifact hygiene

The initial repository-target CLI test attempt failed only because Windows
could not create a build-script output path under the existing repository
`target`; the identical test command passed with `CARGO_TARGET_DIR` outside the
repository. Generated `node_modules`, Cargo target data, web/desktop `dist`,
Playwright results, editor files, and the pre-existing local DOCX remain ignored
or locally excluded and are not release source files.
