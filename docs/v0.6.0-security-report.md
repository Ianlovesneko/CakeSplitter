# CakeSplitter v0.6.0 Security Report

## Scope and method

The focused review compared the v0.6 CLI and Batch Job implementation with the
immutable `v0.5.0` baseline. It covered parser limits, dependency planning,
dispatch, cancellation, state persistence and recovery, output and package
identity, receipts, JSON/JSONL contracts, and the production tests. No full
historical security discovery scan was restarted.

## Result

No Critical, High, or actionable Medium finding remains from the validated
v0.6 scope. The review confirmed bounded specification admission, deterministic
graph execution, literal local paths, no shell/process/network capability,
checksummed atomic run state, cancellation persistence, resume digest and
identity checks, stable JSONL run IDs, redacted receipts, and preserved Cake
Package format `1.0` behavior.

The detailed evidence is in
[`v0.6-security-review.md`](v0.6-security-review.md) and
[`v0.6-automation-validation.md`](v0.6-automation-validation.md).

## Dependency status

`npm audit` and `npm audit --omit=dev` reported zero vulnerabilities. `cargo
audit` exited successfully with zero vulnerability advisories and 17 accepted
transitive Tauri/GTK and Unicode maintenance warnings. These remain documented
maintenance risk for the unsigned local preview.

## Accepted risks

Native identity guarantees depend on Windows filesystem semantics and may fail
closed on network shares, removable media, virtualization layers, or unusual
filter drivers. Cake Package hashes provide integrity, not authenticity,
encryption, or signatures. The process-local active-batch limit does not fence
an independent process. Browser Compatibility Mode remains memory/download
constrained. Public GitHub publication remains deferred until v0.8.0.
