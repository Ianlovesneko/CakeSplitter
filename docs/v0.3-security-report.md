# CakeSplitter v0.3.0 Security Report

Date: 2026-07-17
Phase 11 scan: `af610f5a-6060-4ab9-819f-d4e51c488ce9`

## Result

No unresolved Critical or High issue remains. The sealed Phase 11 review
validated four findings—2 Medium and 2 Low—and all four were remediated before
this release gate.

## Remediated findings

| Finding | Severity | Final control and evidence |
|---|---|---|
| SEC-CS-001: same-size source change during native Split | Medium | Stable source handle/identity, metadata and path-rebinding checks, preflight and streaming SHA-256 comparison, final revalidation, rollback; six mutation/replacement tests and independent harness blocked |
| SEC-CS-002: alternate navigation replaces cached shell | Medium | Canonical marked HTML policy, redirect/opaque/type/origin checks, scoped static caching and cleanup; seven VM tests, offline Edge test, and original poisoning condition blocked |
| SEC-CS-004: Clear All undone by late persistence | Low | Serialized generation barrier, stale-write deletion, Worker cancellation acknowledgement, OPFS cleanup and stale-message rejection; 19 store tests and real Edge OPFS test |
| SEC-CS-003: Unicode bidi terminal spoofing | Low | Visible `Bidi_Control` escaping for human output and JSON-safe escaping for Inspect; five captured-CLI integration tests covering all 12 controls |

Detailed root causes, files, and reproduction evidence are in
[`v0.3-phase11-remediation-report.md`](v0.3-phase11-remediation-report.md).

## Browser privacy and storage

Production Edge network and API instrumentation observed only same-origin GETs
for static application assets. It observed no transmission of file contents,
filenames, paths, manifests, Slices, hashes, package IDs, task metadata, handles,
or private error details. The CSP contains `connect-src 'none'`.

The service worker caches only a marked canonical shell and declared same-origin
static assets. Alternate, redirected, unmarked, opaque, query-bearing, and
user-data responses cannot become the shell. OPFS stores bounded JSON task
metadata only. Clear All fences old writes and deletes the controlled directory.

## Direct Folder decision

Direct Folder Mode remains disabled because supported browser APIs do not
provide portable atomic no-replace publication. The UI and Worker fail closed.
No directory is requested and no direct output or cleanup is attempted. The
generic future adapter contract is tested but is not treated as browser support.

## Accepted risks

- Native source stability is a fail-closed multi-pass identity protocol, not an
  immutable filesystem snapshot. A hostile or privileged filesystem can change
  state after the final observation.
- Browser download prompts, download history, available memory, Blob limits,
  quota, and platform behavior remain browser/OS controlled.
- Compatibility Mode is limited to 256 MiB, 1,000 Split downloads, and 10,000
  selected files; practical limits may be lower.
- Cake Package 1.0 has SHA-256 integrity but no creator signature or package
  authenticity.
- Same-origin host compromise is outside controls of already-delivered code.
- The Clear All generation coordinates one running app context. Concurrent
  trusted tabs remain a bounded local-hardening case, not an authoritative file
  content boundary.
- Automated browser certification is limited to current desktop Edge on the
  recorded Windows host.

## Conclusion

The release gate found no unresolved actionable Medium, Critical, or High
security issue. Low-risk limitations are explicit and Direct Folder Mode stays
fail-closed.
