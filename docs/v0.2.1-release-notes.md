# CakeSplitter v0.2.1 Release Notes

CakeSplitter v0.2.1 is a hardening source release for the v0.2 implementation.
It adds no new user-facing workflow.

## Security and correctness

- Native `.partial` publication now uses atomic no-replace operations on
  Windows, Linux/Android, and Apple platforms.
- Native staged outputs are checked by filesystem identity, size, and SHA-256
  immediately before and after publication.
- Direct browser folder publication is disabled until equivalent guarantees can
  be implemented safely.
- Every Worker request and response is validated at runtime.
- Failed inspection is rendered as a failed/danger result, never green success.
- CLI diagnostics escape untrusted control characters.
- Rust and TypeScript reject the same Windows reserved and non-portable names.

## Browser release boundaries

- Direct Folder Mode is disabled as a fail-closed security decision.
- Compatibility Split buffers one completed Slice, and Compatibility Merge
  buffers the rebuilt output, within the documented 256 MiB operation limit.
- Large operations remain subject to browser memory, download, and platform
  constraints; CakeSplitter does not claim unlimited browser support.
- Browser processing remains local and has no upload path.
- CakeSplitter Desktop is not part of this release.

Future reconsideration of Direct Folder Mode is scoped in the
[security backlog](backlog-direct-folder-mode.md); the mode is not restored by
this release.

## Resource controls

- 16 MiB manifest limit;
- JSON nesting depth 16;
- 50,000-Slice format limit;
- 200 UTF-8 byte portable filename limit;
- 10,000 selected browser files;
- 256 MiB browser compatibility Split/Merge limit; and
- 1,000 browser Split downloads.

## Compatibility

Manifest format remains `cakesplitter` version `1.0`. v0.2.1 is compatible with
valid v0.2 packages that already satisfy the now-explicit limits and portable
filename rules. Packages using reserved, overlong, or otherwise non-portable
names are rejected.

See the [test report](v0.2-test-report.md),
[security report](v0.2-security-report.md), and
[accepted risks](v0.2-security-report.md#remaining-accepted-risks).
