# CakeSplitter v0.4.0 Security Report

Date: 2026-07-19

## Result

No unresolved Critical, High, or actionable Medium security issue remains in
the v0.4.0 release candidate. The sealed v0.4 review validated seven findings:
three Medium and four Low. All seven have production-path remediations and
deterministic regression coverage.

A final bounded security diff reviewed the release-finalization patch from
commit `1cad698e1e78366decf591f281a15442440c6e6c`. It closed 16 changed
source/config rows and both dependency lockfiles with full-file receipts. No
plausible candidate survived discovery, so the workflow did not open empty
validation or attack-path phases. The earlier sealed repository scan was not
restarted or modified.

## Finalization hardening

Installed-app validation found that **Clear All** deleted task/history rows but
left bounded quarantine diagnostics in SQLite. This did not restore a validated
finding, expose file bytes, or bypass task authority, but it contradicted the
documented privacy meaning of Clear All and was treated as release-blocking.

`TaskStore::clear_all` now deletes `tasks` and `quarantine` and advances the
epoch in one transaction. SQL and commit failures propagate, delayed writers
remain epoch-fenced, and the production UI proof now leaves both tables empty.
The regression test seeds a quarantined row and verifies that Clear All removes
it while rejecting a delayed write from the prior epoch.

## Native filesystem and task boundaries

Desktop selection tokens are short-lived and narrowly scoped. Persisted tasks
retain durable Windows volume/file identities, hashes, package membership, and
checkpoints; the runtime never treats path text, filename, size, or timestamp
alone as identity. Reparse ambiguity, replacement, inaccessible identity, or
changed package membership fails closed.

Native publication uses task-owned partials, identity and content revalidation,
and atomic no-replace operations. A final manifest or rebuilt output is not
published after a binding failure. Task admission, startup recovery, history,
metadata, Slice plans, and package enumeration are bounded in Rust before
expensive work or persistence. Renderer button state is not a security control.

## Browser privacy and capability review

The desktop capability set contains the CakeSplitter commands and core event
support needed by the main window. It has no HTTP, updater, shell, process,
telemetry, analytics, or unrestricted filesystem capability, and the production
window loads bundled local content.

The Web app retains `connect-src 'none'`, no network fallback, and a
same-origin canonical-shell service-worker policy. Browser processing remains
local; files, paths, manifests, Slices, hashes, task metadata, and errors are
not uploaded. Browser Direct Folder Mode remains disabled because portable
atomic no-replace publication cannot be proven with the supported browser APIs.

package version, dependency edge, source URL, checksum, npm resolved URL, or npm
integrity value changed.

## Accepted risks and limitations

- The v0.4.0 NSIS installer and executable are unsigned. Windows SmartScreen
  may show an unknown-publisher warning; users must verify the published
  SHA-256 manifest.
- Native support is Windows 10/11 x64 on local filesystems with stable native
  identity. Network, removable, synchronized, virtualized, and identity-poor
  filesystems may fail closed.
- A hostile kernel, privileged process, filesystem filter, or storage device is
  outside the application trust boundary.
- Restart recovery is Slice-boundary resume, not arbitrary-byte resume. A
  partially written task-owned file may require manual cleanup when ownership
  cannot be proven safely.
- Uninstall preserves local task data for safe reinstall recovery. Clear All
  removes managed task/history/quarantine metadata but never deletes user
  packages or rebuilt outputs.
- Web Compatibility Mode is limited to 256 MiB per Split or Merge, 1,000 Split
  downloads, and 10,000 selected files. Practical browser memory, Blob,
  download, quota, and platform limits may be lower.
- Cake Package 1.0 uses SHA-256 for integrity but has no signature, encryption,
  publisher authenticity, or backup redundancy.
- Automated browser certification covers the recorded Windows/Edge host, not
  every WebView2, browser, or enterprise policy combination.
- The informational Rust dependency warnings above remain accepted until their
  upstream Tauri paths can be replaced without broad release risk.

## Conclusion

The v0.4.0 security gate passes. All seven sealed findings are remediated, the
Clear All privacy mismatch is fixed, dependency audits report zero
vulnerabilities, and the bounded finalization diff introduced no new plausible
security finding.
