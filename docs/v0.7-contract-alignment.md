# CakeSplitter v0.7 Machine-Readable Contract Alignment

## Scope

This bounded development checkpoint resolves the highest-priority blocker from
the v0.7 repository-history audit. It aligns the real Batch CLI JSON/JSONL
output with the published schemas and TypeScript validators, restores the
previously blocked validation environment, and does not begin publication,
installer, authorship, license, security-report classification, or v0.8 work.

The starting audit checkpoint was commit `1242fdae6dc0c185e0e73ccdfa9c19c7484a18c1`
on `feat/v0.6-cli-developer-workflows`. The immutable `v0.6.0` tag still points
to `91a5cf482e63757b8050a7803adb19510c3825f1`. This work is on
`feat/v0.7-public-hardening`.

## Original mismatch

The Rust CLI already emitted `command: "batch"`, top-level `runId`, batch and
operation lifecycle event names, and `not-ready`/interrupted batch states.
The published CLI schemas omitted `batch`, omitted those event names and
statuses, and did not describe top-level batch metadata. The TypeScript types
and runtime validators made the same omission. Batch plan operation summaries
also lacked the common operation fields required for a stable final contract.

## Canonical contract decision

CLI schema version remains `1`; Batch Job schema version remains `1`; Cake
Package format remains `1.0`. The correction matches the existing documented
intent rather than changing field meaning:

- every final result keeps the common envelope;
- loaded batch results add top-level `runId`, `jobName`, `jobSpecDigest`,
  `failurePolicy`, `operationCounts`, and `operations`;
- early batch errors carry the established `runId` even when no Job metadata
  could be loaded;
- batch JSONL events have a stable top-level `runId`;
- operation-scoped events expose their operation ID in the top-level
  `operationId` and payload;
- sequence numbers are contiguous and monotonic; and
- exactly one terminal event is emitted, with no later events.

The application development version is `0.7.0-dev`. The public format and
machine schema versions were intentionally not incremented because this is a
runtime/validator correction to the intended schema-1 contract.

## Implementation and tests

Rust output was updated in `crates/cakesplitter-cli/src/contract.rs` and
`crates/cakesplitter-cli/src/batch.rs`. The final envelope now promotes batch
metadata, batch event emission uses operation-scoped IDs, and sequence
overflow fails closed. The JSON schemas, shared TypeScript types, and runtime
validators now cover batch commands, statuses, lifecycle events, batch
identity, safe numeric bounds, operation summaries, and stream invariants.

Sanitized cross-language fixtures are in
`tests/fixtures/cli-contract/`. Rust and TypeScript tests validate the fixtures
and assert stream sequencing, stable run identity, and terminal behavior.

## Production captures

The release/debug CLI executable was run against disposable synthetic fixtures
for:

- version, split, inspect, verify, and plan final JSON;
- split JSONL;
- batch validate, batch plan, batch run, and batch status JSON;
- batch run JSONL; and
- invalid Batch Job, preflight-not-ready, and batch-failure outputs.

Each capture was independently parsed, validated against the published JSON
Schema, validated through the TypeScript runtime validator, checked for the
expected exit code, checked for empty diagnostic stderr, and checked for raw
ANSI leakage. Batch JSONL streams passed stable-run and terminal-event checks.

D: approximately 432 GB free. The normal build recreated

## Focused security and privacy review

The contract diff was checked for JSON/JSONL injection, raw newlines and ANSI
controls, path and secret leakage, unsafe technical messages, unsafe integer
sequences, duplicate or post-terminal events, run/operation identity confusion,
stdout/stderr mixing, and validator bypass. Output remains serialized through
the existing terminal-safe writer, errors remain bounded and redacted, and
machine diagnostics remain on stderr.

## Remaining limitations

Command-specific `result` payloads remain intentionally extensible objects;
the versioned envelope and batch operation summary are the stable machine
contract. Early batch errors cannot expose Job metadata that was never safely
loaded. This checkpoint does not claim a public release, signed tags,
installer validation, or v0.8 readiness.
