## Canonical findings and remediations

### `csf_6bfbe37d31cd74bb6b1e8bf2`

**Windows in-place source mutation can produce a per-Slice-verified but
unrebuildable package** (`core-resumable-split-stream-integrity`, occurrence
`occ_38bf870e653aabf57a9c4752`).

Root cause: Split's original-file digest, streamed Slice bytes, and final
per-Slice checks could be derived from different source reads. A timed
modify-copy-restore operation could leave individually self-consistent Slices
whose concatenation did not equal the Manifest original hash.

Remediation: immediately before Manifest publication, the production Split path
reopens every published Slice in checkpoint order, revalidates native identity,
exact length, exact EOF, and per-Slice SHA-256, hashes the exact concatenated
published stream, and requires that stream hash to equal the baseline source
hash. Recovered and already-published Manifest paths apply the same equality.
Any mismatch returns `source_changed`; no final Manifest is published.

The unchanged sealed harness previously printed
`VULNERABLE_BEHAVIOR_REPRODUCED=true`: Split and Verify succeeded, the Manifest
and Slice-stream hashes differed, and Merge rejected the package. Against the
remediated production core, the unchanged harness exits 101 at its old success
`unwrap` with `SourceChanged`, before it can print any vulnerable-success
assertion. An independent deterministic production-path regression confirms no
Manifest exists. Stable Split immediately passes Verify and Merge, and rebuilt
bytes and SHA-256 exactly match the source.

### `csf_316f53e3dd0de1ce8867816d`

**Durable Merge tasks are not bound to the package selected at enqueue time**
(`runtime-input-binding-001`, occurrence
`occ_5f1dc8bd39d29b6a9d4d4c73`).

Root cause: persisted Merge state retained raw paths and plan metadata but not
the exact package state validated when the user enqueued the task.

Remediation: task-state schema version `2` persists a versioned package binding
atomically with Merge, Inspect, and Verify tasks. It includes native Manifest
and directory identity, exact Manifest-byte SHA-256, the parsed format-1.0
Manifest, ordered Slice names and identities, and a sorted physical Slice-set
membership digest. Execution and restart recovery reopen and compare the
package before work. Merge reads identity-checked handles, hashes each Slice on
the actual copy path, and revalidates package membership immediately before
final output publication. No package input is consumed after that boundary.
Mismatch returns `package_identity_changed`, does not
advance progress, does not create output, and never overwrites the stored
trusted binding.

Production integration tests enqueue package A, replace it with a same-path
valid package B while execution is paused, and confirm failure with no output.
Restoring the original identities and retrying succeeds with exact A bytes.
Restart recovery similarly rejects a same-name/same-size Slice replacement and
accepts the restored original.

### `csf_37799f0a8fc30ac823f952a7`

**Inspection results can persist an unbounded number of unexpected Slice
names** (`runtime-inspection-bounds-003`, occurrence
`occ_fb710c6035dd4b5b07a2b122`; merged Tauri instance `tauri-002`).

Root cause: package-folder discovery and core inspection walked every physical
entry and retained every unexpected `.slice` name. Runtime persistence, IPC,
and UI work amplified that unbounded physical cardinality.

Remediation: one Rust-authoritative, non-recursive enumerator now serves folder
selection, binding, Inspect, Verify, and Merge. It rejects reparse entries and
enforces all limits before classifying or persisting a result. The detailed
limits and rationale are in [v0.4-native-security-limits.md](v0.4-native-security-limits.md).
The central values are 65,536 physical entries, 51,024 `.slice` candidates,
1,024 retained unexpected diagnostics, 200 filename bytes, 24 MiB aggregate
enumeration metadata, 24 MiB serialized inspection output, zero recursion, and
20 UI-rendered rows per issue category.

Pure boundary tests cover exact-limit and plus-one entry, candidate, filename,
metadata, and diagnostic cases without constructing oversized collections.
Real filesystem tests cover exact 1,024 diagnostics, plus-one rejection,
reparse rejection, cancellation, and no recursion. A runtime integration test
confirms an oversized result produces neither a persisted result nor an IPC
completion event.

### `csf_3c9b706fc47cdc6eb3f0617b`

**A rejected task snapshot can disable bootstrap listeners and Clear All
recovery** (`frontend-bootstrap-recovery-001`, occurrence
`occ_74bc41c501e0da233f2abd8d`).

Root cause: startup awaited and parsed the initial task list before registering
task, drop, and close listeners. One rejected list aborted the effect, leaving
the UI without updates and without a usable Clear All recovery route.

Remediation: listeners are independently registered first with
`Promise.allSettled`; one failure cannot remove successful subscriptions.
Runtime information, tasks, and settings then load independently. Every event
is parsed in an isolated handler, task revisions prevent a late stale snapshot
from overwriting a newer event, and the merged task view is capped at 564 rows.
Snapshot failure produces an explicit recovery state while Clear All remains
available.

The Rust store validates schema, checksum, UUID, application/format versions,
state transitions, progress, plans, paths, package bindings, results, failures,
and checkpoints before recovery. It enforces 64 nonterminal rows before decode,
loads only a 20-record bounded diagnostic overflow sample, prunes terminal
history to 500, isolates corrupt rows, and preserves an unsupported future
database as a renamed local evidence file before starting a clean current
store. A real SQLite stress test with 2,112 nonterminal and 1,500 terminal rows
finishes with exactly 64 recoverable rows, 500 history rows, and 20 bounded
quarantine samples.

## Focused security recheck and accepted limitations

The post-fix review was bounded to the four Low paths, shared identity and
enumeration helpers, task persistence/bootstrap, IPC, UI reconciliation, and
new tests. It found Rust-authoritative controls on every production path, no
frontend-only security decision, no permissive fallback, no Cake Package 1.0
change, and no new shell, network, telemetry, update, arbitrary-filesystem, or
overwrite capability. No Critical, High, or new actionable Medium issue was
introduced. All four canonical Low findings are remediated.

Accepted limitations:

- Windows local filesystems provide the validated native handle semantics;
  identity-poor, network, removable, virtualized, or unusual filesystems may
  fail closed and require reselection.
- A package is not claimed immutable after an operation returns. Later changes
  are detected by durable binding, Verify, or Merge.
- A Split integrity rejection can leave identity-owned incomplete Slices for
  manual cleanup, but never a final Manifest or an apparently complete package.
- The explicit 1 GiB streamed validation profile remains intentionally ignored
  in this bounded task; the ordinary large-file production integration path ran.
